# AIELTS

**IELTS practice with specific, bilingual AI feedback.** AIELTS evaluates Writing answers against the supplied task and Speaking responses against the four official criteria. It offers recorded or uploaded audio, timed interview practice, inline corrections, Task 1 charts whose actual values reach the evaluator, and optional cross-device history.

The displayed bands are **AI estimates, not official IELTS scores**. Writing requires a task prompt for Task Achievement. Speaking needs pronunciation evidence from audio before it shows a complete overall band. A key-free sample demonstrates the interface; live analysis needs a server-side Gemini key. See the [portfolio case study](docs/PORTFOLIO.md), [evaluation status](evals/report.md), and [evaluation method](evals/README.md).

```bash
npm ci
npm test
npm run lint
npm run build
```

CI runs these checks on every push and pull request. A public Vercel deployment also requires Upstash Redis REST credentials so the AI rate limits are shared across function instances.

IELTS band шкаласы бойынша сөйлеу мен жазуды бағалайтын AI құралы — тіл үйренушілерге, презентация дайындаушыларға және IELTS/TOEFL тапсырушыларға арналған.

## Мүмкіндіктер

- **Дауыс → мәтін.** Chrome/Edge-те браузердің Web Speech API-і бірден тірі транскрипт береді (кілтсіз). Firefox пен Safari-де Web Speech жоқ — онда жазба серверге барып, Gemini транскрипциялайды.
- **Айтылым бағасы.** IELTS Speaking-тің төртінші критерийі. Жазбаны Gemini тыңдап, band қояды және нақты сөздерді бөліп көрсетеді: «bicycle → bi-SIGH-kul, екпін басында болуы керек». Акцент кемшілік болып саналмайды — тек түсініктілік бағаланады, ресми дескриптор солай.
- **Аудио файл жүктеу.** Микрофонмен сөйлеудің орнына дайын жазбаны беруге болады — mp3, m4a, wav, ogg, flac. Файл браузерде ашылып, WAV-қа айналдырылады, содан кейін транскрипцияланып, толық бағаланады. Ұзын файл бас жағынан қиылады (төменде қараңыз), ал нәтижеде ол туралы ескерту тұрады.
- **Өз жазбаңызды тыңдау.** Сөйлеген кезде дыбыс та жазылады — транскриптпен қатар өзіңізді тыңдай аласыз.
- **Сөйлеу көрсеткіштері.** Қарқын (сөз/мин), артық сөздер, қайталаулар, ұзақ кідірістер. Кідірістер дыбыс толқынынан **өлшенеді**, болжанбайды.
- **Үлгі нәтиже.** Кілтсіз, тіркелусіз, бірінші секундта нағыз нәтиже қалай көрінетінін көруге болады.
- **Speaking сұхбаты.** Емтихан алушы сұрағын **сіздің жауабыңызға қарап** құрастырады — дайын тізім емес: «қыс өте суық» десеңіз, келесі сұрақ сол туралы болады. Толық емтиханды (үш бөлім, 11 кезек, ~12 минут) да, **бір бөлімді бөлек** те өтуге болады — Part 2-ні үшінші рет жаттыққанда сегіз артық сұраққа отырудың қажеті жоқ. Part 2-де нақты cue card пен бір минуттық дайындық таймері бар. Соңында сұхбат бір баллмен бағаланады, нақты емтихандағыдай.
- **Academic Writing Task 1.** График, диаграмма, пирог, кесте — төрт негізгі түрі, SVG-мен беттің өзінде салынады. Ең маңыздысы: **графиктің нақты сандары бағалаушыға беріледі**, сондықтан ол «сіз 6.2 деп жаздыңыз, ал графикте 1.3» деп нақты айта алады. Суретті жүктеу жолында бұл мүмкін емес еді.
- **Тапсырмалар банкі.** Дайын IELTS Writing/Speaking тапсырмалары + емтихан таймері. Өз тапсырмаңызды да жазуға болады.
- **IELTS band бағасы.** 0–9, жарты балл қадаммен, әр режимнің төрт ресми критерийі бойынша: Writing-те Task Achievement, Coherence and Cohesion, Lexical Resource, Grammatical Range; Speaking-те Fluency and Coherence, Lexical Resource, Grammatical Range, Pronunciation. Бұл AI бағасы ресми емтихан нәтижесі емес.
- **Мәтін ішіндегі түзетулер.** Қателер түпнұсқа мәтінде белгіленіп, төмендегі тізіммен нөмірленеді.
- **Қайталанатын қателер.** Барлық талпыныс бойынша қателер санатқа бөлініп жинақталады: «Артикльдер — 8 талпыныстың 6-уында, барлығы 14 рет». Бір талдау мұны айта алмайды.
- **Тарих және прогресс.** Әр талпыныс `localStorage`-та сақталады, балл динамикасы графикпен көрсетіледі, алдыңғы талпыныспен айырма (+0.5 / −0.5) шығады.
- **PDF / басып шығару.** Нәтиже панелін мұғалімге жіберуге болады.
- **Екі тіл.** Интерфейс те, кері байланыс та қазақ және ағылшын тілдерінде. ҚАЗ/ENG қосқышы екеуін бірден ауыстырады — API жауабы екі тілде де келетіндіктен, тіл ауыстырғанда қайта сұраныс жіберілмейді.

## Іске қосу

```bash
npm install
cp .env.example .env.local   # GEMINI_API_KEY жетеді
npm run dev
```

Бір ғана `GEMINI_API_KEY` бүкіл сайтты жүргізеді — мәтін де, айтылым да. `DEEPSEEK_API_KEY` міндетті емес: қосылса, мәтін критерийлері соған ауысады.

`npm run dev` кезінде `api/` ішіндегі функциялар Vite dev-серверіне қосылады (`vite.config.js` ішіндегі `serverlessApi` плагині), сондықтан локалда да, Vercel-де де бір код орындалады.

Керісінше, тек `DEEPSEEK_API_KEY` қойылса, сайт жұмыс істейді, бірақ айтылым бағаланбайды әрі дауыс тану Chrome/Edge-пен шектеледі — аудио тек Gemini арқылы өтеді. AI Studio қазір `AQ.Ab…` пішіміндегі кілт береді; ескі `AIza…` кілттері 2026 жыл бойы қолданыстан шығарылуда. Код екеуін де қабылдайды.

## Модельдер және жауаптың пішімі

Екі endpoint бар, себебі DeepSeek-те аудио моделі жоқ:

| | Не істейді | Провайдер |
|---|---|---|
| `api/analyze.js` | Транскрипттен оқылатын критерийлер, түзетулер, кері байланыс | DeepSeek **немесе** Gemini |
| `api/speech.js` | Транскрипция + Pronunciation критерийі | Тек Gemini |

**Мәтін жағы провайдерге байланбаған.** `resolveProvider()` кілттерге қарайды: `DEEPSEEK_API_KEY` болса — DeepSeek (бағалау промпты соған бапталған), болмаса — Gemini. Демек:

- **Бір ғана `GEMINI_API_KEY`-мен бүкіл сайт жұмыс істейді** — тегін лимитпен, DeepSeek мүлдем керек емес.
- Кейін DeepSeek сатып алсаңыз, кілтті қосу жеткілікті — кодта бір жол да өзгермейді.

Gemini OpenAI-дің wire пішімін өз мекенжайында ұсынады, сондықтан екінші SDK керек болмады — бұрыннан бар `openai` пакеті, тек `baseURL` мен кілт бөлек.

Шақыру реті браузерге қарай өзгереді. Chrome-да транскрипт әлдеқашан бар, сондықтан **екі сұраныс қатар** кетеді. Firefox/Safari-де алдымен Gemini сөйлеуді мәтінге айналдырады, содан кейін DeepSeek бағалайды — амалсыз тізбектей.

Модель мен тариф өзгеретіндіктен, бір талдаудың нақты құнын провайдер панелінен тексеріңіз.

Маңызды техникалық жайт: DeepSeek-те JSON Schema **мәжбүрлеу жоқ** — `response_format: {type: 'json_object'}` тек жарамды JSON екеніне кепілдік береді, оның пішініне емес. Оның үстіне құжаттамада «кейде бос жауап қайтарады» деп жазылған. Сондықтан:

- жауаптың пішімі промптқа үлгі ретінде енгізіледі,
- қайтқан JSON [`api/schema.js`](api/schema.js) арқылы тексеріледі,
- пішім сәйкес келмесе, нақты қателер модельге қайта айтылып, бір рет қайталанады,
- баллдар жарты балл торына дөңгелектеледі (модель 6.37 берсе, «6.4» деген болмайтын баға көрсетілмес үшін).

Промпт үлгісі де, валидация да **бір ғана дескриптордан** шығады — екеуін бөлек ұстаса, бірінші өңдеуден кейін-ақ бір-бірінен ажырап кетеді. Gemini де сол механизмді қолданады (`speechSchema()`), сондықтан екі endpoint бір қорғаныс қабатының артында тұр.

### Task 1 графигі неге сурет емес

Оңай жол — қолданушы емтихан суретін жүктеп, оны vision моделі оқыса болар еді. Бірақ ол кезде **модель графикті өзі оқып шығуы** керек, ал ол қателеседі — сонда «кандидат санды дұрыс оқыды ма?» деген сұраққа сенімді жауап жоқ.

Сондықтан графиктер [`src/lib/charts.js`](src/lib/charts.js) ішіндегі деректен салынады. Нақты сандар белгілі болғандықтан, олар промптқа қоса жіберіледі, ал бағалаушыға «кандидат келтірген әр санды және әр трендті осы деректермен салыстыр» деп тапсырылады. Task 1-дің Task Achievement критерийі негізінен осыған сүйенеді.

Түстер тексерілген палитрадан, бекітілген слот ретімен алынған. Бес слот **іргелес жұптар** бойынша барлық түс ажыратпаушылық тексерісінен өтеді — сызықтар, топталған бағаналар және пирог сегменттері тек көршісімен салыстырылатындықтан, дәл сол тізім қолданылады. Алтыншы санат жаңа түс алмай, «Other»-ге қосылуы керек.

Бестің үшеуі ақ бетте 3:1 контрасттан төмен, сондықтан валидатор «көрінетін белгі» талап етеді: әр пирог сегментінде мәні жазулы, әр графикте легенда бар. **Ол белгілерді алып тастауға болмайды** — талап солармен орындалып тұр.

### Сұхбат қалай бағаланады

Емтихан жоспары [`src/lib/interview.js`](src/lib/interview.js) ішінде — таза функциялар, браузерсіз тестеледі. UI ештеңе шешпейді, `stageAt` не десе, соны көрсетеді. Сессияның жалғыз күйі — өткен кезектер тізімі; курсор бөлек сақталса, ол транскриптпен келіспей қалуы мүмкін еді.

Бөлімді бөлек өту `scope` арқылы: `planFor('part2')` жоспардың сол бөлігін ғана қайтарады, ал `stageAt`, `progressAt`, `isComplete` бәрі сол қысқартылған жоспармен жұмыс істейді. Бір бөлім жеке бағаланғанда промптқа «бұл толық емтихан емес, қысқалығы үшін баллды түсірме» деген жол қосылады — Part 1 жауаптары әдейі қысқа, оны толық емтихандай бағаласа, ой дамыта алмау деп оқылар еді.

Part 3-ті жеке өтсеңіз, оның арт жағында Part 2 карточкасы болмайды. Ондай кезде емтихан алушыға тақырыпты өзі таңдау тапсырылады — әйтпесе ол болмаған әңгімеге сілтеме жасап бастайды.

Аяқталғанда сұхбат екіге бөлініп жіберіледі:

- `text` — **тек кандидаттың сөзі**, біріктірілген;
- `task` — емтихан алушының сұрақтары.

Бұл бөлу кездейсоқ емес. Түзетулер `text` ішінен verbatim дәйектеліп, сол жерде белгіленеді — егер емтихан алушының сұрағы сонда болса, ол кандидаттың қатесі ретінде белгіленіп кетер еді. Тестпен бекітілген.

Осы бөлудің арқасында `analyze.js`, `annotate.js`, тарих, қателер жинағы, прогресс графигі — бәрі сол күйінде қайта қолданылады, сұхбат үшін жаңа механизм жазылмады.

**Айтылым бір ғана жазбадан бағаланады** — ең ұзын жауаптан, яғни әдетте Part 2 монологінен. Он бір жазбаны жіберу он бір сұраныс тұрар еді, ал бір тұтас үзінді бандты негіздеуге жеткілікті; нақты емтиханда да әсер сол монологтан қалыптасады. Сондықтан толқыннан алынған кідіріс өлшемдері бүкіл сессияны сипаттамайды — `audioCoversAllSpeech: false` деген жалау соны айтады, ал метрика сол кезде болжамға қайта оралады. Әйтпесе бір кезектің тыныштығы он бір кезектің тыныштығы ретінде көрсетілер еді.

### Жүктелген файл қалай өңделеді

Жүктелген файл — жазба жасаудың басқа жолы ғана, одан әрі бәрі бірдей. Мәтін болмағандықтан, ол Firefox жүретін жолмен кетеді: алдымен Gemini транскрипциялап, айтылымды сол өтуде бағалайды, сосын мәтін критерийлері шығады. Төменгі қабаттар аудионың қайдан келгенін білмейді.

Пішім шектеуі жоқ дерлік: `decodeAudioData` браузер аша алатынның бәрін ашады (mp3, m4a, wav, ogg, flac, көп жағдайда mp4-тің дыбыс жолы да), ал әрі қарай бәрібір WAV-қа қайта кодталады. Ашылмаған файл нақты хабармен қайтарылады.

Метриканы есептегенде бір айырма маңызды: **мәтін осы аудиодан шыққанда** толқын мен сөздер бірдей үзіндіні сипаттайды, сондықтан қию екеуін де бірге қысқартады да, кідіріс өлшемдері жарамды күйінде қалады. Ал мәтін басқа жерден келсе (Chrome-дағы тірі транскрипт немесе сұхбаттың он бір жауабы), толқын сөздерден қысқа болады — сонда өлшемдер тасталып, болжамға оралады. Әйтпесе бір үзіндінің тыныштығы бүкіл жауаптың тыныштығы ретінде көрсетілер еді.

### Аудио неге WAV болып жіберіледі

Екі шектеу дизайнды анықтады:

1. **Gemini іс жүзінде тек `wav` мен `mp3` қабылдайды.** Құжаттамада ogg/aac та бар, бірақ олар 400 қайтарады. MediaRecorder болса Chrome-да `webm/opus`, Safari-де `mp4/aac` береді — екеуі де жарамайды. Сондықтан браузерде `decodeAudioData` → `OfflineAudioContext` арқылы 16 kHz mono-ға түсіріліп, WAV-қа кодталады ([`src/lib/audio.js`](src/lib/audio.js)).
2. **Vercel функциясының денесі 4.5 MB-тан аспайды** және оны өзгерту мүмкін емес. 16 kHz mono 16-bit — секундына 32 KB, демек шама ~140 секунд. Одан ұзақ жазба айтылымсыз, ескертумен талданады. JSON емес, шикі бинар жіберіледі — base64 бюджеттің үштен бірін тегін жеп қояр еді.

PCM-ді қолға алудың екінші пайдасы бар: **кідірістер енді өлшенеді**. Бұрын олар тану жүйесі фразаны қашан бекіткеніне қарап болжанатын, ал ол шындықтан кешігеді. Енді толқын энергиясынан саналады, шекара бөлменің шуына бейімделеді.

```bash
vercel
```

Vercel панелінде `GEMINI_API_KEY`, `UPSTASH_REDIS_REST_URL` және `UPSTASH_REDIS_REST_TOKEN` environment variable-лерін қосыңыз (қаласаңыз `DEEPSEEK_API_KEY` де). `api/` қалтасы автоматты түрде serverless функция ретінде танылады. Ортақ Redis есептегіші бапталмаса, AI endpoint-тері 503 қайтарады.

Қосымша (міндетті емес): `RATE_LIMIT_PER_HOUR` (әдепкі 10) және `SPEECH_RATE_LIMIT_PER_HOUR` (әдепкі 20) — бір IP-ден сағатына рұқсат етілген сұраныс саны. Екеуі бөлек есептеледі, сондықтан аудио шегі мәтін талдауының шегін жеп қоймайды.

## Деректер қайда сақталады

| | Кірмеген (қонақ) | Google арқылы кірген |
|---|---|---|
| Тарих | браузердің `localStorage`-ы | Supabase (Postgres) |
| Басқа құрылғыда көріне ме | жоқ | иә |
| Браузер тазаласа | жоғалады | сақталады |
| Шектеу | соңғы 40 талпыныс | соңғы 200 талпыныс |

Кіру **міндетті емес** — сайт тіркелусіз де толық жұмыс істейді. Қонақ ретінде жиналған тарих алғаш кірген кезде автоматты түрде аккаунтқа көшіріледі, сосын localStorage тазаланады (сол себепті екі рет жүктелмейді).

Талданатын мәтін өзі ешқашан бөлек сақталмайды — тек талпыныс жазбасының ішінде. Кірмеген жағдайда ол браузерден шықпайды.

## Supabase баптау (міндетті емес)

Аккаунтсыз жұмыс істегіңіз келсе, бұл бөлімді өткізіп жіберіңіз — `VITE_SUPABASE_*` айнымалылары болмаса, кіру батырмасы мүлдем көрінбейді.

1. [supabase.com](https://supabase.com) → жаңа жоба ашыңыз.
2. **SQL Editor** → [`supabase/schema.sql`](supabase/schema.sql) ішіндегі кодты қойып, **Run**. Бұл `attempts` кестесін және Row Level Security ережелерін жасайды.
3. **Authentication → Providers → Google** → қосыңыз. Google Cloud Console-да OAuth client құрып, Client ID мен Secret-ті қойыңыз. Google жағындағы redirect URI:
   `https://<жоба>.supabase.co/auth/v1/callback`
4. **Authentication → URL Configuration** → Site URL ретінде Vercel мекенжайыңызды, ал Redirect URLs тізіміне `http://localhost:5173` қосыңыз (локалда кіру үшін).
5. **Settings → API** → Project URL мен `anon` кілтті `.env.local` файлына (және Vercel env-іне) қойыңыз.

`anon` кілт — ашық кілт, оны браузерге беру қалыпты жағдай. Қауіпсіздікті RLS қамтамасыз етеді: әр SQL сұранысы `auth.uid()` арқылы шектеледі, сондықтан бір қолданушы екіншісінің деректерін оқи да, өшіре де алмайды.

## Ескертулер мен шектеулер

- **Тірі транскрипт браузерге тәуелді.** Chrome/Edge — сөйлеп тұрғанда мәтін бірден шығады. Firefox/Safari-де ол жоқ, сондықтан мәтін тек талдаудан кейін, Gemini транскрипциялаған соң көрінеді. `GEMINI_API_KEY` қойылмаса, бұл браузерлерде сөйлеу режимі жұмыс істемейді.
- **Сұхбатта әр жауап мәтінге айналады.** Тірі транскрипт жоқ браузерде «Келесі сұрақ» басылғанда жазба Gemini-ге жіберіліп, жауап транскрипцияланады; келесі сұрақ сол жауапқа сүйенеді және қорытынды баға барлық жауапты қамтиды. Толық сұхбат үшін бұл 11 қосымша аудио сұранысқа дейін жұмсайды. Транскрипция сәтсіз болса, кезек сақталады — қайта көруге немесе мәтінді қолмен енгізуге болады.
- **Артық сөздер әлі де шамамен — Chrome-да.** Тану жүйесі «um», «uh» дыбыстарын мәтінге жеткізбей тастайды, ал талдау экрандағы мәтін бойынша жүреді (түзетулер сол мәтінде белгіленуі керек). Firefox/Safari-де транскрипт Gemini-ден келеді әрі verbatim, сондықтан ол жақта сан нақты. Промпт бұл айырманы модельге әр жағдайда бөлек айтады.
- **Кідірістер енді өлшенеді.** Дыбыс толқынынан, тану жүйесінің уақытынан емес. Бөлме шуы жоғары болса шекара автоматты бейімделеді; дыбыста динамика мүлдем болмаса, сан ойдан шығарылмай, бос қалдырылады.
- **Rate limit жария деплойда ортақ Redis-те сақталады.** Әр функция инстансы бір есептегішті қолданады. Redis істемесе, AI сұранысы 503 қайтарады; локал әзірлеуде ғана жадтағы шек қолданылады.
- **Дыбыс жазбасы сақталмайды, бірақ жіберіледі.** Талдау басталғанда жазба айтылымды бағалау үшін `api/speech.js` арқылы Gemini-ге барады — тек сол бір сұраныс үшін. Ешқайда жазылмайды: localStorage-қа да, Supabase-ке де түспейді, бетті жаңартсаңыз жоғалады. Тарихта тек мәтін мен нәтиже қалады. `GEMINI_API_KEY` қойылмаса, жазба құрылғыдан мүлдем шықпайды.
- **Сұхбат тегін квотаға тәуелді.** Толық емтихан сұрақ дайындауға 11 шақыру жұмсайды. Нақты қолданыста олардың арасында адам сөйлеп тұрады, сондықтан лимитке жетпейді, бірақ жылдам басып өтсеңіз Gemini-дің тегін тарифі 429 қайтаруы мүмкін. `api/interview.js` бір рет күтіп қайталайды; одан кейін қайталау батырмасы шығады, ал жиналған кезектер жоғалмайды. Бір бөлімді бөлек өту шақыру санын 2–5-ке дейін түсіреді.
- **Сұхбат тарихы Supabase схемасын жаңартуды талап етеді.** Ескі базада `mode` бағанында `check (mode in ('speak','write'))` шектеуі тұр, ал `create table if not exists` оны кеңейтпейді. Миграция [`supabase/schema.sql`](supabase/schema.sql) басында жазылған. Жаңартпасаңыз, кірген қолданушыда сұхбат сақталмайды, ал қонақта жұмыс істей береді.
- **Ұзақ жазба бас жағынан қиылады.** Шек — ~140 секунд (Vercel-дің 4.5 MB дене шегінен шығады). Одан ұзақ жазба қабылданбай қалмайды: алғашқы 140 секунды тыңдалып, баға сол үзінді бойынша қойылады, ал нәтиже панелінде ол ашық жазылып тұрады. Айтылымды бағалауға екі минуттық үзінді әбден жетеді; шектеу жүктеу көлемінен туындайды, ұзақ жауапты бағалау мүмкін емес болғандықтан емес.
- **Кірмеген қолданушының тарихы тек осы браузерде.** Кірген соң Supabase-ке көшеді (жоғарыдағы кестені қараңыз).
- **Талпыныстар өзгертілмейді.** `attempts` кестесінде `update` политикасы әдейі жоқ — жазба тек қосылады және өшіріледі.
- **«Сөйлеу» мен «Жазу» режимдерінің мәтіндері бөлек** сақталады — қосқышты ауыстырғанда бір-біріне араласпайды.
- **API кілт браузерге түспейді** — тек serverless функцияда қолданылады.
- **Жаңа тіл қосу:** `src/i18n.jsx` ішіндегі `translations` объектісіне және `api/schema.js` ішіндегі `bilingual()` тораптарына кілт қосу жеткілікті.
- **Басқа модельге көшу:** провайдерге тәуелді код тек екі файлда — `api/analyze.js` (мәтін) және `api/speech.js` (аудио). Екеуі де OpenAI пішімін қолданады, сондықтан `baseURL` мен модель атын ауыстыру жеткілікті. Егер жаңа провайдер JSON Schema-ны мәжбүрлей алса, валидация қабатын алып тастауға болады — бірақ ол зияны жоқ қорғаныс.
